# Change: keybindings

**Status**: draft
**Date**: 2026-09-27
**Author**: fisher

关联：细化 `command-manager-tui.md`「TUI 交互」与 `tui-page-layout.md` 三区键位。本文档为键位唯一权威来源，与旧文档冲突处以本文档为准。

## Summary

`Tab` 在三区之间循环切换焦点，`↑/↓` 语义随焦点区域变化。输入区不接受自由文本命令行：`#` 弹命令库列表、`/` 弹内置命令列表，二者必须是首字符，其后字符为过滤词；`Enter` 选中绑定，`Alt+Enter` 提交执行。

## 总则

* **`Enter` = 选中**（绑定列表高亮项 / 进入二级列表），**`Alt+Enter` = 提交执行**。两条例外见「输入区 · 例外条款」。
* **不做默认动作**：任何执行都必须由用户显式提交，程序不代为推测意图。
* **提示行**（交互区第 2 行，屏幕最底部）是全部错误/警告的唯一落点；**任意按键事件即清空提示**，与该键是否真正生效无关。
* 同一时刻只有一个区域持有焦点，重叠键按焦点区域解释。

## 全局键位（任意焦点下有效）

| 键 | 动作 |
|---|---|
| `Tab` / `Shift-Tab` | 焦点在三区循环：交互 → 状态 → 输出 → 交互；选择列表展开时**先收起列表再切焦点** |
| `Ctrl+C` | 退出确认：首次按下提示行显示「再按 Ctrl+C 退出」，2s 内第二次按下退出程序（退出前 kill 全部运行中 Job，见 `command-manager-tui.md`「退出清理」）；2s 内按任意其他键取消提示 |
| `Esc` | 逐层取消：关二级列表（退回一级）→ 关一级列表（回初始态）→ 初始态下等同首次 `Ctrl+C` 提示 |

退出提示状态为 `Ctrl+C` 与 `Esc` **共享**：提示已显示时，2s 内只有 `Ctrl+C` 触发退出，`Esc` 与其他键一样仅取消提示。

## 输入区（交互区域，默认焦点）

### 触发与过滤

| 键 | 动作 |
|---|---|
| `#` | 首字符输入时打开命令库列表 |
| `/` | 首字符输入时打开内置命令列表 |
| 其他可打印字符 | 首字符位置**一律忽略**（不入框、不报错，但按总则清空提示行）；已有触发符时追加到尾部作为过滤词 |
| `Backspace` | 删除尾部一个字符；删至只剩触发符时列表重开为全量，删至空框时列表关闭回初始态 |
| `Ctrl+U` | 清空整行输入框，列表关闭回初始态 |

* **无光标**：不支持 `←` `→` `Delete` 与任何行内光标移动，只能尾部追加与删尾。
* 过滤规则：**子串匹配、大小写不敏感**，每次输入实时刷新列表。过滤词永不作为命令执行。
* 匹配字段：`#` 列表按条目 `name` 匹配；`/` 列表按内置命令名匹配；recent 二级列表按副本 `name` 匹配。
* 匹配数为 0 时渲染**空列表框**（只有边框），不收起列表。

### 列表与提交

| 键 | 动作 |
|---|---|
| `↑` / `↓` | 列表展开时移动高亮（超过 10 条时列表内滚动）；列表收起且输入框为空未绑定时召回 recent 历史（见「历史召回」）；其余收起场景**无动作**（不切焦点、不重开列表） |
| `Enter` | 选中：绑定高亮项并把显示文本补全进输入框，列表收起 |
| `Alt+Enter` | 提交：执行输入框当前绑定的 entry，随后清空输入框、解除绑定、关闭列表 |

绑定与解绑：

* `Enter` 选中后，输入框持有「显示文本 + 绑定 entry」两部分状态。`#` 列表选中补全为 `#<name>`。
* **继续打字即解绑**，回到过滤模式：列表按新的输入内容重新展开与筛选。
* 提交执行的是**绑定的 entry 结构**，不是显示文本。

### 历史召回（recent `↑/↓`）

初始态（列表收起、输入框为空且未绑定）下，`↑/↓` 浏览 recent 列表（「提交即写」维护的 MRU，队首最新），不弹选择列表：

| 键 | 动作 |
|---|---|
| `↑` | 进入/继续召回：首次绑定队首最新条目，再按依次取更旧一条；到最旧一条停住 |
| `↓` | 召回态下取更新一条；最新一条再按 `↓` 清空输入框回到初始态；空框直接按 `↓` 无动作 |

* 召回等同 `Enter` 选中：显示文本补全为 `#<name>`，输入框持有绑定的 recent 副本；`Alt+Enter` 按「执行绑定 entry 结构」规则原样执行（hosts/env/cwd 保留）。
* 召回后继续打字或退格 → 沿用「继续打字即解绑」进入过滤模式，召回游标同时取消。
* `Tab` 切焦点、`Ctrl+U` 清空、提交执行后召回游标清零；`Tab` 不清显示文本与绑定（沿用焦点切换保留规则），清空后再次 `↑` 从队首重新开始。
* recent 为空时 `↑/↓` 无动作。

错误路径（均在提示行显示红字，不执行任何命令）：

| 场景 | 行为 |
|---|---|
| 空框按 `Alt+Enter` | 忽略，清空输入框，红字提示 |
| 有输入但未绑定（没按过 `Enter`）就按 `Alt+Enter` | 红字提示，不执行；**不**自动取高亮第一项 |
| 过滤词无匹配时按 `Alt+Enter` | 红字提示（属未绑定的一种） |

### 例外条款

总则为「`Enter` 选中绑定、`Alt+Enter` 提交执行」。内置命令链路有两处偏离，因为内置命令与历史副本都不可编辑、无需用户二次确认：

| 例外 | 行为 | 原因 |
|---|---|---|
| `/` 一级列表 | `Alt+Enter` 等同 `Enter`，均为进入二级列表 | 内置命令没有「绑定 entry」这一步，选中即进入，两键无差别 |
| recent 二级列表 | `Enter` **直接执行**该历史副本，不等 `Alt+Enter`；执行后输入框清空、列表关闭 | 副本与库解耦、内容不可改，回填输入框无意义；直接执行也绕开首字符 `#`/`/` 限制 |

### 二级列表（`/recent`）

* 进入时**输入框清空**，过滤词从零开始。
* **忽略首字符限制**：二级列表是特殊状态，任意可打印字符均作为过滤词参与子串匹配。
* 最多显示 10 条，`↑/↓` 滚动。
* 用 `Backspace` 或 `Ctrl+U` 清空输入框后**回到初始态**（一级列表也关闭，不是退回一级列表）。
* `Esc` 在二级列表下退回一级列表，输入框恢复为 `/`（逐层取消，见全局键位）。

## 状态区（Job 列表）

| 键 | 动作 |
|---|---|
| `↑` / `↓` | 切换选中的 Job 行；选中即决定输出区显示哪个 Job 的输出。Job 行数超出状态区 20% 高度上限时，同键驱动列表滚动 |
| `Enter` | 重跑选中行对应的命令：新起一个 Job，不覆盖旧 Job；按「提交即写」规则同时 push 进 recent（见 `command-manager-tui.md`） |
| `x` | 清除**选中的**已退出（`exit N`）Job 行；选中行运行中时忽略该键 |

清除后选中焦点下移到相邻行（已是末行则上移）；Job 列表清空后输出区进入空态。

* 状态区 `Enter` 直接执行，与输入区 `Enter`（仅选中绑定）语义不同。这是有意保留的差异：状态区不存在「选中再提交」两步语义，选中行已确定目标，`Enter` 即重跑。
* 不提供「清除全部已退出 Job」快捷键，逐行 `x` 清除即可。列入范围外候选。

## 输出区（滚动缓冲）

| 键 | 动作 |
|---|---|
| `↑` / `↓` | 按行滚动 |
| `PgUp` / `PgDn` | 按页滚动 |
| `End` | 跳到缓冲底部并恢复自动跟随 |
| `Home` | 跳到缓冲**最早保留行**（只留尾部 2000 行，非进程输出的真实开头） |
| `c` | 清空当前选中 Job 的缓冲 |

滚动离开底部后暂停自动跟随；新输出仍写入缓冲，仅不重绘视口。

## 焦点与键位作用域规则

* 输入区焦点时常驻显示光标（无行内移动，光标恒在行尾）；状态区/输出区焦点时输入行保留内容与绑定状态，但输入光标隐藏，按键不再落入过滤词。
* 选择列表 popup 仅在输入区焦点下展开；焦点离开输入区时列表收起，**绑定状态与显示文本保留**——切回输入区焦点后可继续 `Alt+Enter` 提交。
* 列表展开时按 `Tab` / `Shift-Tab`：**先收起列表，再切换焦点**。列表不跨焦点存活，避免焦点已离开输入区而列表按键归属不明。

## 风险：`Ctrl+Enter` 终端不可辨，改用 `Alt+Enter`

Linux 终端传统上把 `Enter` 和 `Ctrl+Enter` 都送成同一个字节 `0x0D`（CR），应用层无法区分；termion 不实现 Kitty keyboard protocol / `modifyOtherKeys` 等扩展键协议，拿不到带修饰键的区分信号。故提交键定为 `Alt+Enter`。

`Alt+Enter` 的传输形态是 `ESC` `0x0D` 两字节序列，实现约束：

* 输入线程解析 `termion::input::Keys` 时，`ESC` 后紧跟其他字节的组合会被报为 Alt 修饰键事件；若 termion 版本拆成独立 `Alt('\r')` 或 `Esc`+`Enter` 两个事件，需按「`ESC` 紧接 `Enter`（同一批读入）= Alt+Enter」合并判定。合并判定放在**输入线程**完成（见 `command-manager-tui.md`「线程职责与并发边界」），主循环只收合并后的事件。
* 代价：单独按 `Esc` 键时无法即时与 Alt 前缀区分，需短超时（50ms，以一次批量读取为界）判定为独立 Esc——`Esc` 仅用于取消列表/退出提示，延迟无感知影响。主循环因此用 `recv_timeout` 而非纯阻塞 `recv`（见 `command-manager-tui.md`「模块结构」）。
* **开工前必做**：用临时 keydump 程序在目标终端实测 `Alt+Enter`、单独 `Esc`、`Esc` 后快速 `Enter` 三种输入的字节流与事件序列，据此定解析规则（见 `command-manager-tui.md`「Implementation Plan」第 6 步）。
* `Alt+Enter` 保留而非用裸 `Enter` 提交，是为输入框后续能力扩展预留键位（当前 `Enter` 已被「选中」占用）。

## Affected Code

键位表实现落在 `src/event.rs`（按键解析、ESC 前缀合并）、`src/picker.rs`（两级列表状态机、绑定/解绑、过滤）与 `src/app.rs`（全局键、焦点分派、状态区/输出区键位）。提示行渲染落在 `src/layout.rs`。
