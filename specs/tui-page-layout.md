# Change: tui-page-layout

**Status**: draft
**Date**: 2026-09-27
**Author**: fisher

关联：本设计扩展 `command-manager-tui.md` 的界面部分，新增三区页面布局。键位一律以 `keybindings.md` 为准，本文档只定布局结构与渲染行为，不定义快捷键。

## Summary

TUI 页面从上到下划分为三个区域：状态区域、输出区域、交互区域。区域**不画边框**，相邻区域之间用一条整宽横线分隔。支持多条指令并发执行、输出定时刷新、输入框触发键弹出两级选择列表。交互区第 2 行为**常驻提示行**（错误/警告落点）。

## 布局结构

```
 ▶ cargo clippy --all-targets   [running 00:12] pid 4812   ┐ 状态区 (Status)
 ▶ cargo test                   [running 00:03] pid 4899   │ height = Min(1)，按需增高，上限 20%
 ✓ build.sh                     [exit 0]                   ┘
                                                              ← 状态区底部空行（固定 1 行）
── clippy-all ─────────────────────────────────────────────  ← 分隔线①：嵌当前 Job 名
 warning: unused variable: x                               ┐ 输出区 (Output)
  --> src/main.rs:3:9                                      │ height = Min(剩余全部)
 …（滚动缓冲，自动跟随尾部）                                 │
       ┌ 选择列表 popup ────────────────┐                   │ ← popup 覆盖输出区下缘
       │ ▸ clippy-all    cargo clippy … │                   │   保留完整边框，不改分区切分
       │   clean         cargo clean    │                   │
       └────────────────────────────────┘                   ┘
───────────────────────────────────────────────────────────  ← 分隔线②：纯横线
 > #clip│                                                  ┐ 交互区 (Input)
   无匹配项 / spawn failed: … / （空白）                     ┘ height = Length(2)，提示行红字或空
```

实现：ratatui `Layout::vertical([Min(1), Length(1), Min(0), Length(1), Length(2)])` 五段切分——三区 + 两条分隔线。

* **状态区**行数 = 活跃 Job 条目数，受 20% 终端高度上限约束；超出部分**可滚动查看，不回收**（见「状态区域」）。状态区底部另固定留 **1 行空行**再接分隔线①，不计入 20% 上限；极矮终端下空行在分隔线之后才分配。
* **输出区**吃掉剩余空间，极矮终端下最先被压缩（最小 0 行）；选择列表以 **popup 形式覆盖输出区下缘**，不参与切分、不改变任何区域高度。
* **交互区常驻 2 行**：第 1 行输入框，第 2 行提示行。提示行无消息时渲染为空白，**不动态增减**——避免每次报错时输出区高度抖动闪烁。

### 分隔线

* 三区均不画边框；两条分隔线各占 1 行、整宽 `─`，计入切分，高度固定不随状态变化；
* **分隔线①**（状态区 / 输出区之间）：嵌入输出区当前跟随的 Job 名，形如 `── <name> ───…`；无选中 Job 时为纯横线。输出区持有焦点时整条渲染为青色，否则暗灰；
* **分隔线②**（输出区 / 交互区之间）：纯横线，暗灰，不随焦点变色；
* 焦点指示：状态区靠选中行反显、交互区靠输入光标（见 `keybindings.md`「焦点与键位作用域规则」）、输出区靠分隔线①变色。

### 选择列表 popup

* 位置：底边紧贴分隔线②上方（不遮挡分隔线②），向上延伸覆盖输出区下缘；
* 边框：popup 是浮层，**保留完整边框**（带标题），以便与底下的输出内容区分；
* 高度：前 `min(匹配条数, 10)` 个条目的**总行数** + 2（2 为上下边框）；无 comment 的条目占 1 行，有 comment 的占 2 行。高度只随过滤结果变化，不随高亮移动变化；匹配为 0 时仍渲染**空列表框**（高度 2，只有边框），不收起；输出区放不下时按输出区高度截断，列表内滚动保证高亮条目可见；
* 宽度：输出区宽度，或固定占比（实现时取较易对齐者，不影响行为）；
* 条目第 1 行：高亮标记 `▸` + 显示名 + 完整命令预览（`NAME:` / `ARGS:` / `ENV:` / `CWD:` / `HOSTS:`，过长截断）；
* 条目第 2 行（仅条目有 `comment` 时）：comment 缩进对齐显示名，暗色斜体；始终单行，内含换行替换为空格，过长截断。命令库（`#`）与 recent 二级列表同样渲染，内置命令列表无 comment；
* 过滤只匹配显示名，不匹配 comment；
* 高亮条目整块铺背景色（蓝底白字，含 comment 行），与 `▸` 标记同时出现，随 `↑/↓` 移动；
* 超过 10 条时列表内滚动，高亮行始终可见。

## 状态区域

- 每行一个指令槽位：`名称 | 状态(running/exit N) | 已运行时长 | pid`；
- 状态来源：后台 spawn 的子进程登记表（`Vec<Job>`），运行中条目按 tick 实时累计时长；
- 退出条目保留在列表尾部，非零退出码标红；
- **不自动回收**：Job 行只在用户显式清除（已退出项）时移除。区域高度受 20% 上限约束，装不下的部分通过 `↑/↓` 滚动查看（键位见 `keybindings.md`「状态区」）；
- 多指令并发：同一命令允许重复启动，槽位独立；
- 状态区选中行决定输出区渲染哪个 Job 的输出（选行键位见 `keybindings.md`）；
- **新 spawn 的 Job 自动成为选中行**，输出区立即跟随它（见 `command-manager-tui.md`「运行方式」）；
- 选中行被清除后，选中焦点**下移到相邻行**（已是末行则上移）；Job 列表为空时输出区进入空态。

### 空态

状态区无 Job 时渲染一行提示文案（如 `no jobs — 按 # 选择命令`），不渲染空表格边框。

## 输出区域

- 每个 Job 持有独立滚动缓冲（保留尾部 2000 行）；
- 输出区跟随的 Job = 状态区当前选中行，无独立切 Job 操作；当前 Job 名显示在上方分隔线①中（见「分隔线」）；
- 输出区无边框，视口高度 = 输出区全部行数；
- **定时刷新**：事件循环 tick（间隔 1s）到达时，把各 Job 后台 reader 线程累积的 stdout/stderr 块批量读入缓冲并重绘——避免指令结束后一次性刷出全部输出；
- stdout 与 stderr 按到达顺序混入同一缓冲，不标注来源、不区分样式（见 `command-manager-tui.md`「输出缓冲写入约定」）；
- 自动跟随尾部；向上滚动后暂停跟随，新输出仍写入缓冲、仅不重绘视口；回到底部恢复跟随。滚动与翻页键位见 `keybindings.md`「输出区」；
- `Home` 跳到**缓冲最早保留行**——缓冲只留尾部 2000 行，"顶部"不等于进程输出的真实开头；
- Job 列表为空时渲染空白区域，分隔线①为纯横线；缓冲无内容时同样空白，分隔线①仍显示 Job 名。

## 交互区域

**常驻两行**：第 1 行输入框，第 2 行提示行。

### 输入框

- **不支持自由文本命令行**，本工具只执行命令库中已注册的条目（见 `command-manager-tui.md`「Motivation」边界）；
- **无光标编辑**：只支持尾部追加字符、`Backspace` 删尾字符、`Ctrl+U` 清空整行（键位见 `keybindings.md`「输入区」）；
- **触发键**：`#` 打开命令库列表，`/` 打开内置命令列表。二者**必须是输入框首字符**；首字符不是 `#` / `/` 的输入一律忽略（不入框、不报错）；
- 触发键之后的字符全部视为**过滤词**：子串匹配、大小写不敏感、每次输入实时刷新列表。过滤词永不作为命令执行；
- 退格删至只剩触发符（如 `#`）时，列表重开为全量；删至空框时列表关闭，回到初始态。**列表状态只跟输入框当前内容一致**；
- 输入框持有「显示文本 + 绑定 entry」两部分状态：列表内 `Enter` 选中即绑定该 entry 并补全显示文本，继续打字则**解绑**回到过滤模式；
- 执行提交后输入框清空、绑定解除、列表关闭。

### 两级选择列表

| 级别 | 触发 | 列表内容 | 选中（`Enter`）后 |
|---|---|---|---|
| 一级 · 命令库 | `#` | `commands.toml` 全部条目，按过滤词筛选 | 绑定该 `CommandEntry`，输入框补全为 `#<name>`，列表收起，待 `Alt+Enter` 提交 |
| 一级 · 内置命令 | `/` | 内置命令列表（当前仅 `/recent`），按过滤词筛选 | 进入该内置命令的二级列表（例外条款，见下） |
| 二级 · recent | `/recent` 选中 | 最近执行副本（≤30 条），按过滤词筛选 | **直接执行该副本**，输入框清空、列表关闭（例外条款，见下） |

### `Enter` / `Alt+Enter` 的两条例外

总则是「`Enter` 选中绑定、`Alt+Enter` 提交执行」。内置命令链路有两处偏离，因为内置命令与历史副本都**不可编辑、不需要用户二次确认**：

| 例外 | 行为 | 原因 |
|---|---|---|
| `/` 一级列表 | `Alt+Enter` 等同 `Enter`，均为进入二级列表 | 内置命令没有「绑定 entry」这一步，选中即进入，两键无差别 |
| recent 二级列表 | `Enter` **直接执行**该历史副本，不等 `Alt+Enter` | 副本与库解耦、内容不可改，回填输入框无意义；直接执行也绕开首字符 `#`/`/` 限制与显示文本的冲突 |

### 二级列表规则

- 进入时**输入框清空**（过滤词从零开始）；
- 最多显示 10 条，超出用 `↑/↓` 滚动；
- 二级列表是**特殊状态**：忽略一级列表的首字符限制，任意可打印字符均作为过滤词参与子串匹配；
- 用 `Backspace` 或 `Ctrl+U` 把输入框清空后，**回到初始态**（一级列表也关闭，不是退回一级列表）；
- 副本与库解耦，库条目被改/删后 recent 中的旧副本仍按原内容执行（见 `command-manager-tui.md`「recent 记录规则」）；因选中即执行、不回填输入框，界面上不需要区分副本与库条目的显示前缀。

### 提示行

- 位置：交互区第 2 行，屏幕最底部；
- 内容：红字错误/警告。当前来源包括——空框提交、未绑定就提交、过滤无匹配、`spawn failed: <os error>`、`recent.toml` 写失败；
- 常驻占位：无消息时渲染空白行，**不动态增减高度**；
- 消失时机：**任意按键事件即清空**，与该键是否真正入框无关（被忽略的非法首字符同样清空提示）。

## 事件模型

线程结构（输入线程 / 1s tick 线程 / 每 Job 两条 reader 线程，mpsc 汇入主循环）见 `command-manager-tui.md`「模块结构」线程图，本档不重复。渲染参数归本档所有：

| 参数 | 值 |
|---|---|
| tick 刷新间隔 | 1s |
| 输出滚动缓冲保留行数 | 尾部 2000 行 |
| 选择列表最多显示条数 | 10 条 |
| 选择列表 popup 高度 | 前 `min(匹配数, 10)` 条的总行数 + 2（有 comment 的条目占 2 行） |
| 交互区高度 | 常驻 2 行（输入框 + 提示行） |
| 区域分隔 | 2 条单行横线，区域不画边框；popup 保留完整边框 |
| 状态区高度上限 | 终端高度的 20%（另加底部空行 1 行，不计入上限） |
| 状态区 Job 行数上限 | 无（不回收，滚动查看） |
| recent 条数上限 | 30 条（存储侧规则，见 `command-manager-tui.md`） |
